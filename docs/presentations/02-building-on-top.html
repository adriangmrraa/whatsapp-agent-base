Non-negotiables (AGENTS.md)

Rules every agent — human or AI — must keep

1

Tenant isolation is law. Every tenant-owned query filters by tenant_id; every server action starts with requireTenantId(); agent tools are built inside buildAgentTools(tenantId, …). A global limit(1) is a security bug.

2

Fail closed. Signature, dedup, or CAS uncertainty → no mutation, no reply.

3

Secrets stay server-side. setCredential/getCredential only — never client props, never logs.

4

Provider-agnostic core. Business logic lives in src/lib/engine/ against MessagingProvider — no provider SDKs outside adapters.

5

Idempotent effects. Replies, notifications, provider calls are claimed before they fire.

6

Stay generic. Vertical logic (pizza, clinic, store) goes in your tools/schema extensions — not in the base.

Harness

Schema changes

db:generate needs a TTY; on Windows use generate --custom + hand-written SQL with backfill (nullable → UPDATE → NOT NULL).

Safe test path

Call processInbound() with a fabricated NormalizedInbound against a seeded test tenant — exercises tenant→session→routing without network.
