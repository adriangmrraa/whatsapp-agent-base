WhatsApp Agent Base

A foundation for WhatsApp Business SaaS.

Not an app — a base you build on. Multi-tenant, provider-agnostic, with a durable AI engine, encrypted credentials, and an admin panel. You write your domain; the plumbing is done.

Tenancy

Multi-tenant core

tenant_id on every row. Inbound resolves via channels(provider, externalId); admin resolves via session. Isolation is a security boundary.

Providers

YCloud · Meta · Chatwoot

One MessagingProvider interface, three adapters. Webhooks are thin shells; the engine is shared.

AI

Any OpenAI-compatible model

Per-tenant ai_* config — OpenAI, OpenRouter, DeepSeek, Groq, Ollama. Tools are built per tenant by construction.

Safety

Fail closed

Signature, dedup, or CAS uncertainty → no reply. Idempotent effects. Encrypted secrets. Rate-limited webhooks.

The anti-LLM firewall

The session policy decides before spending tokens

fixed_ack

First casual message → one canned acknowledgment. No LLM.

fixed_clarification

Ambiguous follow-up → one clarifying question, once.

handoff

Human requested → idempotent claims: notify owner once, tell customer once, set override.

blocked / duplicate

Human owns the thread, or the webhook is a replay → silence.

allow_agent

Commercial flow → agent runs with compact session facts, not raw state.

CAS transitions

version counter on session row — racing deliveries can't both pass.

ThreatControl
Forged webhookPer-tenant HMAC signature — never a global secret
ReplayTimestamp tolerance + unique dedup index + CAS
Cross-tenant leaktenant_id NOT NULL + scoped queries + per-tenant tools
Secret exposureAES-256 at rest; UI shows presence only; never logged
Duplicate effectsEffect-claim table — reply/notify once per episode
FloodingRate limit per IP on every webhook
Provider outageQueue + DLQ + circuit breaker; no silent drops
