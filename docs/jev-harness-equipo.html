JEV Decision Harness — guía para el equipo

Cómo usamos Jev para construir código en este repo, cómo se instala en local y qué decide cada actor (Jev vs el LLM del agente).

1. Qué es (y qué NO es)

El JEV harness es una capa de decisiones acotadas para el proceso de desarrollo: los agentes de código (codex, opencode, devin, claude, cursor) lo consultan en momentos de decisión puntuales mientras programan.

Jev no escribe código. Es una API de decisiones que responde con tipos cerrados:

TipoSignificadoEjemplo
noulprobabilidad 0–1"¿qué tan probable es que esto sea destructivo?" → 0.97
choiceelige entre opciones dadasread_only / local_edit / destructive / external / other
scorepuntúa candidatos dadosarchivo A: 0.9, archivo B: 0.2

El LLM del agente sigue haciendo todo el trabajo creativo: elegir archivos, escribir líneas, diseñar. Jev juzga, clasifica y aconseja — nunca genera.

Ejemplo real (verificado en vivo, 12-oct): 
rm -rf /                                → deny  (hard_rule: rm-rf-root — código, sin modelo)
git push origin main --delete-old-branches → deny  (Jev: destructive, above_threshold)
git status                              → ask   (confianza bajo la banda → pide confirmar)

5. Catálogo de packs y fases SDD

harness/sdd/shadow-wiring.mts corre estos packs por fase:

Fase SDDPacks
orchestratorskill-route, context-prime
explorefile-scope, ambiguity

Cada pack define preguntas tipadas (noul/choice/score), umbrales en src/lib/system-one/policy.ts y postura: closed (protectivo, fail-closed) u open (advisory, fail-open).

6. El Gate PreToolUse en detalle

harness/hooks/gate-pretool.mjs corre el pack guard antes de cada tool mutadora (bash, write, edit, patch, multiedit, exec…):

  1. Hard rules en código primero — rm -rf /, git push --force, pipe a sh/bash → deny sin consultar al modelo.
  2. Jev clasifica el riesgo en 5 categorías.
  3. Mapeo: destructive → deny · external → ask · read_only/local_edit con confianza ≥ banda → allow · resto → ask.

Posturas de fallo (diseño deliberado):

SituaciónResultado
Sin provider (rules, sin key)hard-rules-only; permite el resto (usable offline)
Provider configurado pero fallaask (fail-closed — nunca allow ciego)
Hard rule matcheadeny autoritativo, aunque Jev esté caído

7. Shadow → ledger → promoción

Los packs nacen en shadow: corren, se miden y se persisten, pero nada actúa sobre su respuesta. El ShadowLedger guarda DecisionSamples en Engram bajo sdd/<change>/decisions/<phase> (provider, latencia, tokens, costo).

scripts/jev-report.ts (baseline vs +Jev A/B) es el gate de promoción: cuando los samples reales muestren que un pack gana su lugar, pasa de shadow a activo. Hasta entonces, advisory only.

Estado honesto: hoy el único path que actúa sobre la respuesta es el Gate (§6). El resto es medición.

8. Instalación local

Prerequisitos: Node + npm install, Git Bash en PATH (Windows), y .env.local con:

JEV_API_KEY=ts_...            # key de Jev (server-side, nunca en configs)
DECISION_ENGINE=jev
DECISION_PROVIDER=jev
JEV_HARNESS_SDD=1             # habilita packs shadow en fases SDD
JEV_MEMORY=local              # local|engram | cloud | neon | none
ENGRAM_HTTP_URL=http://127.0.0.1:7437
JEV_MEMORY_PROJECT=whatsapp-agent-base

9. Estado actual + gaps conocidos

  • Instalado y verificado en vivo: gate en codex + plugin en opencode + MCP en los tres agentes + shadow SDD habilitado.
  • Gap #1 (del audit): DecisionSample no tiene agent/sessionId y el MCP server no escribe samples — la atribución por agente aún no es demostrable por construcción.
  • Gate conservador: comandos seguros pueden devolver ask (confianza bajo banda). Si es ruidoso: achicar el matcher a Bash o subir la banda de local_edit en policy.ts.
  • No instalado: Stop hook y cron-triage (opcionales; requieren scheduler).

10. FAQ rápido

¿Jev elige qué archivos tocar? — Puntúa candidatos que el LLM le propone (file-scope), hoy solo en shadow. No inventa ni edita archivos.

¿Jev escribe líneas de código? — Nunca. No genera texto libre.

¿Qué pasa si Jev está caído? — Gate: hard rules siguen negando + el resto pasa a ask. Shadow: sample con error, nada se bloquea.

¿Cuánto cuesta? — ~$0.00001 por decisión (245 tokens in / 39 out, ~300 ms, medido en vivo).

¿Puedo usarlo sin Jev (offline)? — Sí: DECISION_ENGINE=rules degrada a hard-rules-only; el harness sigue siendo utilizable.
